# Behavior Tree 시뮬레이터

기존 FSM과 같은 솔루션에 있는 독립적인 C++20 콘솔 프로젝트다.
나무꾼, 상점주인, 주점 주인과 자원 변화·행동 횟수·우선순위를 유지하고,
행동 결정 구조를 Behavior Tree(BT)로 바꿨다. 기존 FSM 헤더나 상태 클래스를 사용하지 않는다.

## Visual Studio에서 사용

1. 상위 폴더의 `FSM.slnx`를 연다.
2. 솔루션 탐색기의 `BehaviorTree`를 시작 프로젝트로 설정한다.
3. 원하는 Debug/Release, x64/x86 구성으로 직접 빌드하고 실행한다.

기존과 같은 v145 도구 집합을 사용한다. 새 프로젝트의 실행 파일과 중간 파일은
`BehaviorTree/bin/<플랫폼>/<구성>/`, `BehaviorTree/obj/<플랫폼>/<구성>/`에 따로 생성된다.
프로젝트 전체에 `/utf-8`을 지정하고 시작 시 Windows 콘솔 출력 코드 페이지도 UTF-8로 설정한다.
개발 과정에서는 빌드·실행하지 않았다.

## 파일과 책임

| 파일 | 역할 |
| --- | --- |
| `bt/BehaviorTree.h` | 상태 반환값, 노드, Sequence, Selector, Repeat, PrioritySelector, Model |
| `bt/Blackboard.h` | 타입이 있는 키로 값을 저장·조회하는 공통 블랙보드 |
| `BlackboardKeys.h` | 공유/개인 데이터 키의 이름과 타입 정의 |
| `Characters.h` | 인물 클래스 선언. 데이터는 상속받은 블랙보드에 보관 |
| `WoodCutter.cpp` | 나무꾼의 행동 트리 구성 |
| `Seller.cpp` | 상점주인의 영업·구매·휴식 트리 구성 |
| `TavernKeeper.cpp` | 주점 주인의 작업·접대 트리 구성 |
| `main.cpp` | 인물 생성과 100틱 갱신 루프 |

인물 클래스는 `bt::Model`을 상속한다. 생성자에서 자신의 트리를 만들고 `SetTree()`로 등록한다.
행동은 `Action` 객체의 람다 함수로 정의한다. 이 함수는 상태를 직접 지정하지 않고 결과를 반환한다.
람다가 인물 객체를 참조하므로 모델은 복사·이동할 수 없다. 공유 블랙보드와 주점 주인은 나무꾼보다 오래 살아야 한다.

## 블랙보드 사용

기존 `World` 구조체와 인물의 개별 수치 멤버를 제거했다.
모든 조건 판단과 행동 데이터 갱신은 `bt::Blackboard`를 사용한다.
트리의 실행 위치와 Running 여부는 노드 자체의 실행 정보이므로 노드 안에 유지한다.

| 범위 | 접근 함수 | 저장 데이터 |
| --- | --- | --- |
| 모든 인물의 공유 블랙보드 | `Shared()` | 판매 요청, 주점 방문 여부, 음주 여부, 상점주인 화장실 이용 여부 |
| 나무꾼 개인 블랙보드 | `Local()` | 나무, 출근 거리, 체력, 코인, 취기, 취침 진행도 |
| 상점주인 개인 블랙보드 | `Local()` | 졸림, 흡연 욕구, 화장실 욕구, 화장실 진행도 |
| 주점 주인 개인 블랙보드 | `Local()` | 설거지 진행도, 청소 진행도 |

`main.cpp`가 공유 블랙보드를 한 개 생성하고 세 인물에게 같은 참조를 전달한다.
공유 키는 인물 생성 전에 초기화한다. 각 인물 생성자는 자신의 개인 키를 초기화한 뒤 트리를 등록한다.
각 모델은 별도 개인 블랙보드를 소유하므로 같은 종류의 인물을 생성해도 개인 값은 분리된다.
공유 요청 키는 현재 한 명의 나무꾼을 위한 구조다. 여러 손님을 지원하려면 손님 ID별 데이터가 필요하다.

```cpp
bt::Blackboard shared;
shared.Set(simulation::keys::SellingWood, false);
shared.Set(simulation::keys::VisitingTavern, false);
shared.Set(simulation::keys::Drinking, false);
shared.Set(simulation::keys::SellerInToilet, false);

simulation::Seller seller(shared);
simulation::TavernKeeper tavernKeeper(shared);
simulation::WoodCutter woodCutter(shared, tavernKeeper);
```

키는 `BlackboardKeys.h`에서 한 번 정의한다. 예를 들어 Coin은 `bt::Key<int>`, SellingWood는
`bt::Key<bool>`이다. 사용 지점마다 문자열과 타입을 다시 입력할 필요가 없다.

```cpp
// 모델의 Action 안에서 개인 데이터 갱신
Local().Get(keys::Coin) -= 5;
Local().Get(keys::Intoxication) += 5;

// 나무꾼이 공유 정보 기록
Shared().Set(keys::SellingWood, true);

// 상점주인의 우선 조건에서 공유 정보 읽기
return Shared().Get(keys::SellingWood);

// 외부에서 인물의 데이터 조회
const int coins = woodCutter.Local().Get(simulation::keys::Coin);
```

`Set(key, value)`는 키를 생성하거나 값을 갱신한다. `Get(key)`는 기존 값의 참조를 반환하므로
`++`, `--`, `+=`도 저장된 값에 직접 반영된다. const 블랙보드에서는 읽기 전용 참조를 반환한다.
초기화하지 않은 키를 읽으면 `std::out_of_range`, 같은 이름을 다른 타입으로 사용하면
`std::logic_error`를 발생시킨다. 기본값으로 오류를 숨기지 않는다. 단일 스레드용이다.
새 데이터를 추가할 때는 키 선언 → 해당 생성자에서 초기화 → 행동/조건에서 사용 순서로 작성한다.
술 제공 대사 함수 호출은 유지하되, 전달되는 코인도 개인 블랙보드에서 읽은 값이다.

## 트리 동작

| 구성 요소 | 의미 |
| --- | --- |
| `Success` | 행동 또는 조건 성공. 상위 노드가 다음 행동을 결정 |
| `Failure` | 조건 불충족 또는 실패. Selector가 다음 후보 확인 |
| `Running` | 진행 중. 다음 틱에 계속 수행 |
| `Action` | 시작·실행·종료 콜백. 완료/중단 시 종료 콜백을 한 번 호출 |
| `Condition` | 데이터 검사만 수행하고 Success 또는 Failure 반환 |
| `Sequence` | 자식을 순서대로 실행. Running 자식의 위치를 기억 |
| `Selector` | 실패한 후보는 건너뛰고 성공/진행 중인 후보를 선택. Running 후보를 기억 |
| `Repeat` | 자식 Sequence가 성공하면 처음부터 반복 |
| `PrioritySelector` | 매 틱 우선 조건을 다시 검사. 고객 요청을 평상시 작업보다 우선 처리 |

한 모델의 `Update()`에서 Action 실행은 최대 한 번이다. 조건 검사와 다음 행동의 시작 콜백은
같은 틱에 처리할 수 있다. 다음 행동의 실제 작업은 다음 틱에 실행한다.
`SetTree()`는 첫 행동의 시작 콜백만 실행하며 데이터를 갱신하는 행동은 실행하지 않는다.
이 규칙으로 나무 베기와 나무 판매가 같은 틱에 동시에 처리되는 것을 방지한다.
`Repeat`는 반복 시작 때 행동 실행을 차단하므로 즉시 성공하는 트리로 무한 루프에 빠지지 않는다.

### 나무꾼

```text
Repeat
└─ Sequence
   ├─ 출근: 거리 5까지 증가
   ├─ 벌목: 체력 -1, 나무 +1
   ├─ 판매: 나무 -1, 코인 +5
   ├─ 주점 방문: 방문 요청 설정 → 한 행동 후 완료
   ├─ 음주: 코인 -5, 취기 +5, 취기 20에서 완료
   └─ 취침: 5행동 후 완료, 종료 시 취기 0·체력 10·거리 0
```

기존과 같이 출근·벌목·판매는 목표에 도달한 다음 틱에 완료를 판정한다.
음주와 취침은 각각 4번째, 5번째 행동에 바로 완료한다.
판매 시작/종료 콜백이 공유 블랙보드의 판매 요청을 켜고 끈다.
방문 시작부터 음주 종료까지 주점 방문 요청을 유지한다.
음주 행동에서 주점 주인의 `ServeDrink()`를 호출해 판매 대사와 나무꾼의 대답을 출력한다.
대금과 취기는 나무꾼 쪽에서만 변경한다. 돈이 부족하거나 제공이 거절되면 취침으로 이어진다.

### 상점주인

최상위에는 화장실 우선순위를 둔다. `Seller::Update()`에서 화장실 이용 중이 아닐 때
개인 블랙보드의 `keys::Toilet`을 1 증가시킨 뒤 트리를 실행한다.
`Toilet >= 10`이면 개점·영업·구매·수면·흡연 어느 행동 중이든 기존 트리를 일시 중단한다.
화장실 행동을 5번 수행한 뒤 욕구를 0으로 초기화한다. 종료한 틱에는 추가 행동을 하지 않고,
다음 틱에 중단했던 정상 트리를 이어간다. 수면·흡연의 남은 수치는 보존된다.
정상 트리의 구매 조건은 복귀 후 다시 검사하므로, 화장실에 있는 동안 들어온 거래 요청도 반영된다.

```text
PrioritySelector [Toilet >= 10?]
├─ 화장실 (5행동 후 Toilet = 0)
└─ 아래의 정상 행동 트리 (중단 시 실행 위치 보존)
```

공유 블랙보드의 `SellerInToilet`은 화장실 행동의 시작/종료 콜백에서 설정한다.
나무꾼의 판매 행동은 이 값이 true이면 나무와 코인을 변경하지 않고 기다린다.
갱신 순서는 나무꾼이 먼저이므로 상점주인이 화장실에 들어가는 틱에는 앞서 나무 한 개를 팔 수 있다.
이는 FSM 버전과 같은 순차 갱신 규칙이다.
우선순위는 **화장실 > 구매 > 정상 영업 및 휴식**이다.

```text
Sequence
├─ 개점 (1행동)
└─ PrioritySelector [판매 요청이 있는가?]
   ├─ 구매 (요청이 지속되는 동안 Running)
   └─ Repeat
      └─ Sequence
         ├─ 영업: 매 행동 졸림·흡연 욕구 +1, 휴식 필요 시 완료
         └─ Selector
            ├─ Sequence: 졸림 > 10? → 수면
            └─ Sequence: 흡연 욕구 > 5? → 흡연
```

수면은 졸림을 1씩 감소시키고 0인 다음 행동에서 완료한다.
흡연은 시작할 때 수치를 5로 설정하고 행동마다 1씩 감소시킨다.
두 조건이 동시에 충족되면 수면이 우선이다. 휴식 도중 조건을 재검사해 영업으로 조기 복귀하지 않는다.
나무 판매 요청이 들어오면 진행 중인 평상시 서브트리를 Reset해 중단한다.
거래 종료 후 영업부터 다시 시작하므로 기존의 강제 Buying → Working 전환과 같은 규칙이다.

### 주점 주인

```text
PrioritySelector [주점 방문 요청이 있는가?]
├─ 손님 접대 (방문/음주 여부에 따라 대화)
└─ Repeat
   └─ Sequence
      ├─ 설거지: 5행동
      └─ 청소: 10행동
```

접대 시 평상시 서브트리를 Reset하지 않고 잠시 갱신하지 않는다.
따라서 실행 중이던 자식 위치와 진행도가 그대로 남는다. 손님이 떠나면 해당 작업을 이어간다.
FSM의 PreviousState 포인터 없이 트리 실행 위치를 보존해 같은 메커니즘을 표현한다.

## FSM 버전과의 관계

현재 상태 enum이나 ChangeState 호출로 전체 흐름을 흉내 내지 않는다.
실행 순서는 Sequence, 행동 선택은 Selector, 반복은 Repeat가 결정한다.
공유 블랙보드의 bool 값은 인물 간 요청/관찰 정보이며, 여러 값이 동시에 참일 수 있다.

갱신 순서는 기존과 같은 나무꾼 → 상점주인 → 주점 주인이다.
다른 인물의 상태를 즉시 바꾸는 대신 요청을 기록하고 상대방 트리가 자신의 차례에 확인한다.
따라서 같은 틱 안에서 인사나 종료 대사가 출력되는 세부 순서는 FSM과 다를 수 있다.
특히 주점 작업 재개는 중단된 노드를 이어가므로 작업 시작 대사를 다시 출력하지 않는다.
자원 변화와 행동 횟수, 구매 우선 처리 및 작업 복귀 규칙은 유지한다.

## 사용자가 실행하며 확인할 지점

다음 값은 코드로 추적한 예상값이며 실행 검증 결과는 아니다.

| 시점 | 예상 |
| --- | --- |
| 첫 판매 진입 | 나무 10개·체력 0, 상점주인 화장실 중에는 판매 대기 |
| 첫 판매 완료 | 코인 50, 주점 방문 시작 |
| 첫 음주 4회 | 코인 50 → 30, 취기 0 → 20 |
| 첫 취침 5회 | 종료 후 취기 0·체력 10·거리 0 |
| 상점주인 첫 10틱 | 욕구가 10이 되어 화장실 행동 시작 |
| 화장실 5번째 행동 | 욕구 0, 공유 화장실 이용 여부 false |
| 접대 전후 | 주점 주인의 작업 종류와 진행도가 보존되고 퇴장 틱부터 다시 증가 |

프로젝트 파일 및 경로는 정적으로 확인했다. 실제 컴파일과 실행 결과는 아직 확인하지 않았다.
